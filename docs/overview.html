p2p-compute Deterministic verification substrate for peer-to-peer compute — project state briefing

Jobs (RISC-V programs + inputs) run on untrusted machines. Every machine executes the same pinned deterministic emulator and emits a hash chain covering the entire execution. Because the execution is byte-for-byte deterministic, a single compared hash is enough to detect any fraud — and the system offers three independent ways to do that comparing, up to and including a zero-knowledge proof of the emulator itself.

The core artifact: a pinned deterministic emulator

The foundation is crates/rvcore — an interpreter for a deliberately small slice of RISC-V (RV64IMC: integer, multiplication, compressed instructions; no atomics, no floating point). Smallness is the point: the entire architectural state is enumerable, so "deterministic" is enforced by construction, not by discipline.

The determinism contract

  • Architectural state = 32 registers + pc + mtvec + mepc + mcause + mstatus + memory — nothing hidden, no flags, no clock, no ambient RNG.
  • Unallocated pages read as zero; writes allocate; flat 4 GiB space; misaligned loads/stores supported (deterministic byte-level split, matching spike/QEMU).
  • Invalid encodings and out-of-range accesses trap; ecall traps (QEMU-compatible syscall mode for the differential); ebreak halts; mret returns to mepc.
  • Every field above is hashed — a forged snapshot cannot carry hidden state past the chain check.

The chunk-hash chain

h_i = BLAKE3( h_{i-1} ‖ x0..x31 ‖ pc ‖ mtvec ‖ mepc ‖ mcause ‖ mstatus ‖ memory_root )

Emitted every chunk_size instructions and at exit. memory_root is a canonical memory digest — one flat BLAKE3 digest over the sorted page indices and their full 4 KiB contents (not a Merkle tree). The chain is the single artifact every verification tier consumes.

CI re-verifies the committed receipt on every run (the zk-receipt job). The sealed artifact set — receipt + guest ELF + job bytes — travels together.

The network layer

  • Identity: Ed25519 keypairs, nonce challenge-response at hello; results signed over their entire content (job id, status, instruction count, full chain, output) via an explicit length-prefixed encoding.
  • Admission proof-of-work: BLAKE3(nonce ‖ counter) to --identity-pow-bits leading zeros, nonce fresh per connection — a banned identity pays to return. This is what makes slashing/bans bite even though keypairs are free.
  • Transport: length-prefixed JSON frames over TCP, TLS 1.3 (rustls) with coordinator certificate + BLAKE3 fingerprint pinning — no CA, no other server accepted.
  • Quorum integrity: results only from dispatched workers; one vote per worker; threshold = strict majority of the dispatched pool (a timeout cannot shrink it); rejected jobs return bonds untouched (slashing requires proof).
  • Content store: BLAKE3-addressed blobs (the "torrent" layer) — descriptor = the torrent file; workers fetch from peers first, coordinator as fallback, every byte hash-verified on arrival.

A worker joining from the open internet

Machine 3 moved to a phone hotspot (a genuinely foreign network), the coordinator exposed through a router port-forward at the real public IP (after discovering an active ProtonVPN was masking it — the first connection attempt dialed the VPN exit node). The WAN peer mined the 22-bit admission proof over the internet, fetched and hash-verified the job blobs across the WAN, executed 16,410 instructions, and produced the exact pinned hash. The zk receipt, end to end

A receipt-carrying worker submitted a signed SP1 receipt for the nano job; the coordinator verified it through the external oracle (key re-derived from the committed guest ELF, binding checked against the descriptor's content ids) and accepted the job on the proof alone — Decision::Accept { zk: true }, zero execution results, no quorum.

Honest limits — what this is NOT

  • Bonds are bookkeeping, not escrow. Slashing edits a JSON ledger; identity cost is proof-of-work, not capital. A determined attacker's cost is compute, not money.
  • The coordinator is trusted for worker selection and ledger keeping. This is verifiable compute for the job client, not trustless compute between strangers.
  • Agreement is not truth. Quorum and disputes verify that copies of our emulator agree; ISA correctness rests on sampled independent evidence (QEMU, official suite). The zk tier collapses the anchor to the emulator source + zkVM soundness — at the nano envelope today.
  • Multi-shard receipts are blocked on SP1 6.8 ("artifact not found" on CPU; shard-boundary crashes on execute). Bigger proofs need newer SP1, a GPU, or a prover market.
  • NAT traversal is router/overlay-assisted (port-forward worked in the demo). Native hole-punching/relay is unbuilt.
